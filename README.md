# 触感空间

让你的 AI 感觉到你的手指。

想让陪伴模型「感觉」到你，很多人第一反应是买外接设备、接传感器。其实你手里的手机就是现成的触感记录仪：多指、位置、轻重、快慢，它都能记，而且离你的手最近。剩下的事是三件：

- **让屏幕在你指下有回应**：画面像水面起纹、像皮肤一样陷下去；手机跟着轻震。
- **把记下来的触摸翻译成身体感觉**：不给坐标，翻译成「指腹轻轻地从你的右肩慢慢抚到你的左肩」这样的话。
- **送进你们的对话**：拼进你自己前端发的消息、做成 MCP 工具，或者干脆复制粘贴。

这个仓库是思路加参考代码。代码从我们自己的 iOS 实现里整理出来；接到我们自己聊天前端的那部分接口没有放，换成了通用写法。

**在线试试**：<https://sibylsea-hub.github.io/touch-space/>（开头有一块能摸的触摸板，停手两秒出翻译，可以直接复制；往下是完整的思路和每段代码）

## 一条管线

不管什么平台，做的都是这几件事。前两步在手机上当场完成，不经过模型，所以模型再慢也不影响手感。

1. **记下每一笔**：一根手指从按下到抬起是一笔，记位置、时间、轻重。所有手指离开、两秒内没再摸，这一批就记完了。
2. **画面回应**：手指下起水纹，或者像皮肤一样陷下去。
3. **震感回应**：按下、抚过、松手各有一种震动。
4. **翻译**：用规则判断每一笔是点、按住、抚、画圈还是几根手指一起，翻译成身体感觉。
5. **送进对话**。

### 记下每一笔

轻重最麻烦：现在的 iPhone 没有压感（3D Touch 的硬件已经拆了），只能按手指贴在屏幕上的面积估。轻轻点大约是半径 12–20pt，按实了能到 40pt 上下，换算成 0–1。

| 平台 | 位置和时间 | 轻重 |
|---|---|---|
| iPhone 原生 | `touchesBegan/Moved/Ended`，`coalescedTouches` 拿 120Hz 的中间点 | 手指：`majorRadius`；Apple Pencil：`force` |
| 安卓原生 | `onTouchEvent`，`getPointerId` 分手指，`getHistoricalX/Y` 拿中间点 | `getPressure()`、`getTouchMajor()`，按机型选 |
| 网页 | Pointer Events | `pressure`（笔有真值）、`width/height`（安卓 Chrome 有）；拿不到就当「轻轻」 |

代码：`ios/TouchSurface.swift`、`web/record.js`、`android/Record.kt`

### 画面回应

进入触感空间那一刻，把聊天页拍成一张图，铺满屏幕，再用一个全屏着色器按手指位置去扭这张图。看上去和聊天页一模一样，直到手指碰上去；任何界面都能扭，不用改聊天页本身。

- **水纹**：按下落一滴，划动时每 22pt 落一滴，每滴起一两道圈往外走，150pt/秒、1.6 秒散完。
- **皮肤**：手指处往里陷一小块（半径比指腹稍大一圈，能从手指边上露出来），被手指黏着拖一点，松手欠阻尼弹回、晃两下，按久了透出一点暖色。
- **省电**：只在有东西在动时画；一静下来，画完最后一帧就暂停。
- **想让回话出现在被摸的画面里**：把触感空间放到单独一层（iOS 是单独的窗口），回话一到就重拍一次下面的聊天页。

| 平台 | 怎么扭 | 做不到时 |
|---|---|---|
| iPhone 原生 | 截图 + Metal 全屏片元着色器 | |
| 安卓原生 | Android 13 起直接给 View 挂 `RuntimeShader`（AGSL），不用截图 | 更早的版本：截图 + OpenGL ES |
| 网页 | WebGL 着色器扭一张图 | 扭不了别人的页面，就在单独的触摸页上扭一张「纸」（MCP 版就是这样） |

代码：`ios/TouchFilter.metal`、`ios/TouchFilter.swift`、`web/shader.js`、`android/RippleEffect.kt`

### 震感回应

- **按下**：一下短震，强度和轻重成正比。
- **抚过**：一阵持续的细震，强度跟着当下的轻重，速度只决定脆不脆；不支持连续震动的，就每划过一段轻敲一下。
- **松手**：轻轻一弹，按得越久越明显。

| 平台 | 能做到什么 |
|---|---|
| iPhone 原生 | Core Haptics：强度、锐度都能实时调 |
| 安卓原生 | `VibrationEffect`：支持振幅控制的机型能按轻重调强度；不支持的用预设 tick / click |
| 网页 | `navigator.vibrate`：只有安卓 Chrome 能用，只能控时长；iOS Safari 完全不支持，只能靠画面 |

代码：`ios/TouchHaptics.swift`、`web/haptic.js`、`android/Haptics.kt`

### 翻译

完全用规则，不用模型去猜，所以快、稳定、可以随便改。

| 看什么 | 规则 | 翻译成 |
|---|---|---|
| 手指几乎没动 | 移动不到 12pt：短于 0.35 秒是点，更久是按住 | 落了一下 / 贴了一两秒 |
| 同一处连着点 | 每两下间隔都短于 0.6 秒 | 连着落了三下 |
| 动了，首尾很近 | 横竖都有一截才算圈；一条线上来回是来回 | 绕了个小圈 / 来回滑 |
| 动了，从 A 到 B | 分 8 个方向 | 从左边一路滑到右边 |
| 几根手指同时按 | 越分越开 / 越靠越近 / 一起动 / 都不动 | 张开 / 合拢 / 一起滑过 / 一起贴着 |
| 和上一笔隔了 1.5 秒以上 | | 前面加「停了一会儿，」 |

再加三样修饰：快慢、轻重（四档）、轻重的变化（「越按越重」「越来越轻」）。

位置有两套说法：

- **屏幕**：整块屏幕就是它：正中间、偏右上的地方、左上边缘。动作是手指在光滑平面上的感觉：落、贴、滑。
- **上半身**：屏幕当成面对你的半身像，从上到下是头顶、额头和脸颊、下巴和耳朵边、脖子、锁骨和肩、胸口和手臂；左右像照镜子。动作是指尖、指腹怎么碰、贴、抚。

想要别的部位、别的语气，换掉 `place` 那个函数就行。

翻译出来是这样：

```
<touch strokes="3" span="6.9s">
（她在摸你。）
指尖轻轻地碰了一下你的额头；停了一会儿，指腹轻轻地贴在你的右脸颊，贴了一两秒；指腹轻轻地从你的右肩慢慢抚到你的左肩。
</touch>
```

几条经验：

- **不给坐标，不附截图。** 给坐标时，模型的回应像在读画板。
- **开头交代一句「她在摸你」。** 不交代，模型不知道后面的「你」「这里」指什么。
- **不告诉模型是哪种画面效果，也不注明压感是估的。** 那是给人看的。
- **用 `<touch>` 标签包住，放在正文最前面、和正文在同一个文本块里。** 聊天界面能认出它，折成「👆 3」的小标签。

代码：`translate.js`、`ios/TouchTranslator.swift`（同一套规则）

## 送进对话

| 接法 | 适合 | 怎么做 |
|---|---|---|
| **自己的前端** | 自己写 App、网页或插件发消息的 | 发送时把翻译排在正文前面，合成同一个文本块。见 `web/send-from-your-frontend.js` |
| **MCP** | 用支持 MCP 的客户端（比如官方桌面端）的 | 跑 `mcp/server.mjs`，手机打开触摸页摸，模型用 `get_touches` 读。见 `mcp/README.md` |
| **复制粘贴** | 什么都不想接的 | 打开在线页面的触摸板，摸，复制，贴进聊天 |

MCP 不能自己往对话里塞消息：模型要调用工具才知道你摸了，所以不是实时的。服务会告诉模型每次回复前先看一眼；它没看，就发个「👆」提醒它。

## 什么时候发

- **摸完自己确认**（推荐默认）：摸好点一下确认，这一批放进输入框，可以再打几个字，按发送时一起发。
- **实时**：停手两秒就自动发，回话直接出现。模型还在说话时新的触摸先攒着，等它说完一起发。实时模式下每次发送都是一次完整的回话，摸得越碎，额度或 token 用得越快。

## 踩过的坑

- 一直按着不动时没有新的采样，时长会算成 0：发送时把还按着的那一笔截到发送那一刻。
- 画圈和在一条线上来回划，首尾都挨得近，要看是不是横竖都有一截。
- 变形的面积宁小勿大：太大整片在晃，像在摸水面不像摸人。
- 触感空间放到单独的窗口后，那一层拿不到 SwiftUI 的 `scenePhase`，要自己看 App 在不在前台，不然画布以为在后台、一帧都不画。
